# API design rules

- REST over HTTPS, JSON, OpenAPI generated by the built-in ASP.NET Core OpenAPI support. The OpenAPI document is the contract, and the TypeScript client is generated from it.
- Resource-oriented URLs with plural nouns, versioned by URL prefix: `/api/v1/orders/{orderId}`. The admin API lives under `/api/admin/v1/...` with separate policies.
- Errors use **RFC 9457 Problem Details** with a stable machine-readable `type` (e.g. `price-changed`, `offer-expired`, `idempotency-conflict`) and a `traceId`. Never leak stack traces, SQL, or supplier error payloads.
- Unsafe booking/payment/refund/cancel operations require an **`Idempotency-Key`** header, scoped to the caller (keys are per customer). A replay returns the original *result*: the same resource (same id), never a second effect. The status code is 200 where the first was 201, and the body is the resource as it is now, which is the same while nothing has changed. The key and its result live in the database, so replays behave the same after a restart. The same key with another payload is 409 `idempotency-conflict`.
- Uncertain or slow operations return `202 Accepted` with a status resource to poll (e.g. an order in `PendingConfirmation`), rather than holding the request open on slow suppliers.
- Status codes: 200/201/202/204, 400 (validation), 401, 403, 404, 409 (state/idempotency/concurrency conflict), 412 (ETag precondition), 422 (business rule, e.g. price changed), 429, 502 (unexpected or unusable supplier response), 503 (provider unavailable).
- Optimistic concurrency on admin edits via `ETag` / `If-Match`.
- Lists use cursor pagination (`?cursor=&limit=`) with a maximum `limit`.
- Money in JSON is `{ "amount": "123.45", "currency": "EUR" }` (amount as a string to avoid float precision loss). Dates are ISO-8601. Local travel times include the zone.
- **No breaking changes within a version.** CI runs an OpenAPI diff. Breaking changes need a new version and a deprecation plan.
- Every endpoint documents its auth policy, request/response schemas, and error types.
